# 设计系统「可爱清新」

> 对应 [产品愿景 §3](../00-product/vision-and-scope.md)、NFR-A11Y-01/02/03。
> 所有 token 定义在 `lib/design/tokens/`，**业务代码中禁止出现硬编码颜色、尺寸、时长**
> （由 lint 规则与 code review 强制）。

## 1. 基调三原则

| 原则 | 具体化 |
|---|---|
| **低压力** | 低饱和、高明度；逾期用暖橙不用红；不做负面反馈 |
| **圆润** | 全局大圆角；圆头线条图标；无锐角、无硬边框 |
| **有呼吸** | 留白充足；阴影柔和宽散；动效带轻微回弹但克制 |

**可爱不能牺牲可读**：正文对比度 ≥ 4.5:1 是硬门槛（NFR-A11Y-01）。
低饱和配色最容易在这条上翻车，因此下表所有对比度**均为按 WCAG 2.1 公式实算所得**，不是估计。

> 实算已经抓到一个真实缺陷：初版把 `semantic.overdue`（`#F5A38C`）直接用作逾期时间的**文字色**，
> 实测对比度仅 **1.94:1**，严重不合格。因此 §2.4 拆成了「填充色」与「文字色」两列 —— 
> 这类错误如果留到实现阶段，只会以「看起来有点淡」的形式被忽略掉。

## 2. 色彩 Token

### 2.1 品牌色

| Token | 亮色值 | 暗色值 | 用途 |
|---|---|---|---|
| `brand.primary` | `#7FD1C1` 薄荷 | `#5FB3A3` | 主行动、选中态、进度条 |
| `brand.secondary` | `#FFB7C5` 樱花 | `#D98C9C` | 次要强调、装饰 |
| `brand.tertiary` | `#FFD79A` 奶油橙 | `#D9AE6E` | 点缀、徽标 |

> ⚠️ **品牌色上不许放白字** —— 白字在 `#7FD1C1` 上实测仅 **1.78:1**。
> 规则：品牌色作填充时，其上文字一律用 `text.onBrand`（`#1F3D37`），实测 **6.62:1** ✅。
> 该深色在 `secondary`（7.21:1）与 `tertiary`（8.67:1）上同样达标，可统一使用。

| `surface.card` | `#FFFFFF` | `#26242C` | 卡片 |

| `border.subtle` | `#EDE7DD` | `#35323C` | 极淡分隔（优先用留白代替线） |

### 2.3 文字

| Token | 亮色 | 实测对比度（vs canvas） | 用途 |
|---|---|---|---|
| `text.primary` | `#3A3742` | **11.26:1** ✅ | 正文、标题 |
| `text.secondary` | `#6E6A78` | **5.08:1** ✅ | 辅助说明 |
| `text.disabled` | `#A9A5B0` | 2.34:1 | **仅用于禁用态**，不得承载信息 |
| `text.onBrand` | `#1F3D37` | 6.62:1（vs primary）✅ | 品牌色填充上的文字 |

暗色主题：`#FFFFFF` on `surface.canvas #1B1A1F` 实测 **17.30:1** ✅。

### 2.4 语义色（填充色与文字色必须分开）

低饱和的语义色适合做**填充**（色条、徽标底、进度段），但作为**文字**几乎全部不达标。
因此每个语义色有两个 token：

| 语义 | `.fill`（填充/色条） | `.text`（文字/图标） | 文字色实测 | 用途 |
|---|---|---|---|---|
| `semantic.done` | `#8FD9A8` | `#417F58` | 4.62:1 ✅ | 已完成 |
| `semantic.soon` | `#FFC97A` | `#94682A` | 4.76:1 ✅ | 即将到期 |
| `semantic.overdue` | `#F5A38C` 珊瑚 | `#A85E45` 陶土 | 4.67:1 ✅ | **逾期** |
| `semantic.info` | `#A8C8F0` | `#3F6FA8` | 5.02:1 ✅ | 信息 |
| `semantic.danger` | `#E88B8B` | `#A85555` | 4.96:1 ✅ | 破坏性操作确认 |

- 逾期刻意不用正红：`#A85E45` 是暖陶土色，能读清但不制造焦虑。这是「低压力」原则的具体落地。
- 暗色主题下 `.fill` 系列在 `#1B1A1F` 上实测 7.0–11.4:1，**可直接兼作文字色**，无需第二套。
- lint 规则：`semantic.*.fill` 出现在 `TextStyle.color` 位置即报错。

### 2.5 分类默认调色板

新建分类时按顺序取用，同屏多分类需可辨：

```
#7FD1C1 薄荷   #FFB7C5 樱花   #FFD79A 奶油   #A8C8F0 天空
#C3B5F0 薰衣草  #F5B7A3 蜜桃   #A8D8B9 嫩芽   #F0C8E0 藕粉
```

⚠️ 这些颜色对**两种表面**（§2.2 的 `surface.canvas #FDFBF7` 与 `surface.card #FFFFFF`）的对比度实测为：

| 表面 | 范围 | 最高者 |
|---|---|---|
| `surface.canvas` | 1.32 – **1.82** | `#C3B5F0` |
| `surface.card` | 1.36 – **1.88** | `#C3B5F0` |
| 合计 | **1.32 – 1.88** | |

全部远低于图形元素所需的 3:1，因此它们**只能做 3px 色条与小色点，绝不能承载文字，
也绝不能是唯一的信息载体**。分类名必须同时以文字出现（见 §8.1）。

## 3. 字体

### 3.1 ⚠️ 字体必须打包，不得运行时下载

`google_fonts` 默认在**运行时从网络下载**字体。这与 NFR-PRIV-01（V1 不联网、不采集）直接冲突，
且首次启动会出现字体闪烁。

**决定**：字体文件作为 `assets/fonts/` 打包进 APK，在 `pubspec.yaml` 声明 `fonts:`。
`google_fonts` 若保留，必须配置为仅使用本地 asset。
**M0 检查表项**：确认 APK 内无运行时字体请求（用模拟器抓包或断网启动验证）。

### 3.2 字族

| 用途 | 字体 | 说明 |
|---|---|---|
| 中文 | 系统默认（Android 为思源黑体系）+ 适度字间距与行高 | 圆体中文字库体积大（常在 5–10MB），V1 不打包 |
| 拉丁与数字 | 圆体（`Quicksand` / `Nunito` 类），随包 | 数字与时间刻度大量出现，圆体在此处贡献最大 |

> 「可爱」主要由圆角、间距、配色、插画承载，**不依赖中文圆体字库** —— 这是体积与观感的权衡。
> 若后续愿意接受体积增长，可在设置中提供「圆体中文」下载开关（V2+）。

### 3.3 字阶

| Token | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `display` | 32 | 1.25 | 600 | 空态大标题 |
| `title.lg` | 22 | 1.35 | 600 | 页面标题 |
| `title.md` | 18 | 1.4 | 600 | 分组标题 |
| `body.lg` | 16 | 1.55 | 400 | 任务标题 |
| `body.md` | 14 | 1.6 | 400 | 正文 |
| `label` | 13 | 1.4 | 500 | 按钮、Chip |
| `caption` | 12 | 1.45 | 400 | 时间、计数 |

**行高偏大**（1.4–1.6）是刻意的：中文在宽松行高下更「轻松」。

### 3.4 缩放是**两层相乘**，golden 必须覆盖到实际最坏值

NFR-A11Y-02 写的是「系统字号缩放至 200%」，而
[配置注册表](settings-spec.md) 里 `theme.fontScale` 的范围是 **0.85–1.4，
且与系统缩放叠加**。三份文档各自的措辞都自洽，合起来却漏了一件事：

```
用户能达到的最坏有效缩放 = 1.4（应用内） × 2.0（系统） = 2.8
```

**没有任何一份文档承认过 2.8 这个数。** 于是「golden 覆盖到 200%」听着像
覆盖了 NFR，实际覆盖不到用户真能造出来的状态 —— 这与 M1 里
「UNTIL 不变式挑的时区跳变都在凌晨，走不到出问题的分支」是同一个形状：
测试看着在测边界，而边界在别处。

**决定：golden 矩阵按有效缩放取三档。**

| 档位 | 有效缩放 | 对应场景 |
|---|---|---|
| 基线 | 1.0 | 默认 |
| 系统上限 | 2.0 | NFR-A11Y-02 的字面要求 |
| **实际上限** | **2.8** | 应用内 1.4 × 系统 2.0，用户可达的最坏值 |

与明暗两主题相乘 = **6 组**。每个纳入视觉回归的组件都要跑满这 6 组。

⚠️ **其中「不破版」这件事不该用 golden 图去断**。拿图比的东西就是快照，
改一个间距 token 就全红，于是被 `--update-goldens` 一把抹平。
「标题不被截断」「操作区不出屏」这类要查渲染树，不产出图片 ——
两类的分法与验证方式见[测试策略 §7.1](../05-engineering/testing-strategy.md#71-断言型与快照型必须用机制分开不是用命名)。

若某个组件在 2.8 下确实无法不破版，那需要一次**产品决策**（下调
`theme.fontScale` 上限、或对该组件声明降级行为），并写进本节 ——
**不接受「测试只跑到 2.0，2.8 的情况没人提过」这种默认**。

## 4. 圆角

| Token | 值 | 用途 |
|---|---|---|
| `radius.xs` | 8 | 小标记、色块 |
| `radius.sm` | 12 | Chip、小按钮 |
| `radius.md` | 16 | 输入框、次级卡片 |
| `radius.lg` | 20 | 任务卡片（主力） |
| `radius.xl` | 28 | 底部弹层、对话框 |
| `radius.full` | 999 | 药丸按钮、头像 |

配置项 `theme.cornerStyle` 提供三档（`soft` / `standard` / `sharp`），
分别把上表整体 ×1.25 / ×1.0 / ×0.5，满足不喜欢大圆角的用户（FR-CFG-02）。

## 5. 间距

4 的倍数：`2, 4, 8, 12, 16, 20, 24, 32, 40, 48`

| 场景 | 值 |
|---|---|
| 图标与文字间 | 8 |
| 卡片内边距 | 16 |
| 卡片间距 | 12 |
| 分组间距 | 24 |
| 页面左右边距 | 16 |
| 触控目标最小尺寸 | **48×48**（无障碍硬要求） |

## 6. 阴影

不用锐利深阴影。统一两级柔和阴影：

| Token | 规格 |
|---|---|
| `shadow.soft` | y=2, blur=12, spread=-2, `rgba(80,70,90,0.06)` |
| `shadow.lifted` | y=6, blur=24, spread=-4, `rgba(80,70,90,0.10)` |

暗色主题下改用**表面提亮**（surface tint）而非阴影 —— 暗色里阴影几乎不可见。

## 7. 动效

| Token | 时长 | 曲线 | 用途 |
|---|---|---|---|
| `motion.fast` | 120ms | `easeOutCubic` | 按压反馈、涟漪 |
| `motion.base` | 200ms | `easeOutCubic` | 展开收起、淡入淡出 |
| `motion.slow` | 320ms | `easeInOutCubic` | 页面转场 |
| `motion.bouncy` | 280ms | `easeOutBack` | **仅限**勾选完成、新增落位 |

**回弹只用在正反馈上**，且幅度限制在 ≤4% 的缩放，避免廉价感。

**所有动效必须可关**：配置项 `theme.reduceMotion`，同时响应系统「减少动态效果」。
关闭时动效时长统一降为 0，但**保留状态变化本身**（不能因为关动效就看不出发生了什么）。
golden 测试覆盖开关两种状态（NFR-A11Y-03）。

## 8. 核心组件规范

### 8.1 任务卡片（最重要的组件）

```
┌────────────────────────────────────────────┐
│ ▎ ○  任务标题                        14:00 │   ▎= 分类色条(3px)
│ ▎    └ 副信息：分类 · 阶段 2/5              │   ○ = 完成圆钮(48×48 触控区)
└────────────────────────────────────────────┘
```

- 圆角 `radius.lg`，内边距 16，阴影 `shadow.soft`。
- 左侧 3px 分类色条 —— **颜色不是唯一信息载体**，分类名同时以文字出现（色觉障碍可用性）。
- 完成钮点击 → `motion.bouncy` 勾选动画 + 卡片淡化，**不立即消失**（给撤销留时间）。
- 逾期：左色条换 `semantic.overdue.fill`，时间文字用 `semantic.overdue.text`（**不是同一个色**，见 §2.4），
  **不加感叹号、不加红底**。

### 8.2 空态

每个视图都要有专属空态：插画 + 一句轻松文案 + 一个明确行动按钮。
**禁止**出现「暂无数据」这种冷冰冰的默认文案。

### 8.3 完成反馈

勾选完成时：卡片轻微回弹 + 一次性的小粒子（3–5 个，200ms 内消失）。
`reduceMotion` 开启时降级为纯色变化。**不做**连击计数、不做打卡天数，避免造成压力。

## 9. 主题装配

- 基于 Material 3 的 `ColorScheme`，但**所有颜色显式指定**，不依赖 `fromSeed` 自动派生
  —— 自动派生会把低饱和色算成高饱和，破坏基调。
- 亮/暗两套完整 `ColorScheme`，暗色不是亮色的机械反转（见 §2 各表的暗色列）。
- 用户可配主色（`theme.primaryColor`），选择后其余颜色按固定规则派生，
  并**自动校验对比度**：不达标时提示并给出最接近的达标色。

## 10. 对比度的自动化守卫

设计文档里的对比度数字会随改色而失效，因此写成测试而不是只写在文档里：

`test/design/contrast_test.dart` 遍历所有「前景 × 背景」的合法组合，断言：

| 组合类别 | 门槛 |
|---|---|
| 正文文字 × 任意表面 | ≥ 4.5:1 |
| 大号文字（≥18px 或 ≥14px 粗体） × 表面 | ≥ 3.0:1 |
| 图标 / 非文字关键图形 × 表面 | ≥ 3.0:1 |
| `text.disabled` | 豁免（不承载信息） |
| `semantic.*.fill` 用作文字 | **直接判失败** |

同时对用户自定义主色的派生结果跑同一套断言 —— 用户能选的颜色范围内不允许出现不达标组合。

> 这条测试必须能被「把某个颜色调淡一点」弄红。M1 的变异演练会验证这一点
> （见[测试策略](../05-engineering/testing-strategy.md) §3.1）。
