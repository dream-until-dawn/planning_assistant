# 探针：24 位色彩空间能否穷举

**结论：能。377 ms。**

## 为什么要探这个

[设计系统 §10](../../../03-design/design-system.md) 要求「用户能选的颜色范围内
不允许出现不达标组合」。`theme.primaryColor` 是用户可配的（[配置注册表](../../../03-design/settings-spec.md)），
所以这条断言的对象是**一个空间**，不是几个样本。

拿几个样本色测通过，证明不了「范围内不允许出现」—— 这与本项目反复撞的
「单样本推全称结论」是同一件事，只是这次的域是颜色。

于是先问一个可测的问题：**全空间到底能不能穷举？** 能的话就不必谈采样。

## 实测

```
穷举 16777216 色 × 6 表面 = 100663296 次对比度计算
耗时 377 ms
```

6 个表面 = canvas / card / sunken × 明暗两主题。

关键在于 sRGB 通道线性化可以查表（每通道只有 256 个取值），
于是每个颜色的相对亮度是「3 次查表 + 2 乘 2 加」。
`math.pow` 只在建表时调 256 次，不在内循环里。

## 因此 §10 的断言口径定为「全集」

不是「若干代表色」，是 **16,777,216 个可选颜色一个不落**。
这与 M1 里扫完整个 tz 数据库（8846 次春季跳变）找「23:59 不存在」的组合
是同一个做法：**域能枚举就枚举，不要采样后声称全称**。

## 这个探针**不是**最终测试

它只回答「穷举可行吗」。真正要断言的是**校验器本身**：

> 对每一个可选颜色，要么被接受（且派生出的整套配色达标），
> 要么被拒绝（且给出的最近达标色确实达标）。

还需要一条「拒绝集非空且边界正确」的证明 —— 否则一个「全部接受」的
校验器也能让「被接受的都达标」这句话为真（因为它同时让派生规则背锅），
而一个「全部拒绝」的校验器则让整个配置项失去意义。

实现时见 `test/design/`。
