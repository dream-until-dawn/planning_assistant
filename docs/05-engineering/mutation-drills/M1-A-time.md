## M4 为什么能逃掉

**因为当时全部 DST 用例都用 `America/New_York`，那是个负偏移时区。**

| 偏移方向 | 真实绝对时刻相对「把墙钟当成 UTC」的位置 |
|---|---|
| 负偏移（`America/New_York` −5/−4） | **之后** |
| 正偏移（`Australia/Sydney` +10/+11） | **之前** |

搜索窗口左端缩掉后，正偏移时区的真实时刻落到窗外，`offsetLo` 取到的是跳变**之后**
的偏移，于是走进「窗口内无跳变」分支并抛 `StateError`。而负偏移的样本全程不碰左端，
所以 8 条 DST 用例一条都没红。

**这不是「样本不够多」，是样本在一个维度上系统性地偏了** ——
所有 DST 样本都来自同一个半球、同一个偏移方向。与
[testing-strategy §1.3](../testing-strategy.md) 记的 freezed 那次同源：
「我手上恰好有的数据」不等于「能支撑结论的样本集」。

## 补的用例

`test/core/time_zone_resolver_test.dart` 新增一组「南半球 DST + 正偏移」：

| 用例 | 期望值来源 |
|---|---|
| Sydney 春季跳表 10-04，02:30 → 03:00 | IANA 规则「十月第一个周日 02:00 开始」+ 手算 2026-10-01 是周四 → 首个周日 10-04 |
| Sydney 秋季回拨 04-05，02:30 取较早 | IANA 规则「四月第一个周日 03:00 结束」+ 手算 2026-04-01 是周三 → 首个周日 04-05 |
| 正偏移时区的绝对时刻早于同值 UTC | 这条是 M4 的**直接判据**，三个正偏移时区参数化 |

手算的两个日期一次对上，未依赖跑一遍看输出。

## 补测后重新注入 M4，确认能红

```
南半球 DST + 正偏移（变异演练 M4 补漏） 春季跳表（10-04）：不存在的 02:30 顺延到 03:00 [E]
  Bad state: 时区 Australia/Sydney 在 2026-10-04 02:30[Australia/Sydney] 处换算失败（无跳变却无解）
```
三条用例全部变红；还原后 50 条测试回绿。

## 顺带记一笔：实现本身也被打回过一次

`resolve()` 初版用「在绝对时刻上二分『当地时间 ≥ 目标』」，秋季回拨用例当场变红 ——
**当地墙钟在 UTC 上不是单调的**，01:00–01:59 会出现两次，二分的前提不成立。
春季跳表恰好单调，所以那组过了、这组没过。

改成「候选偏移 + 二分找跳变点」后两组都过。这段经过写进了 `resolve()` 的文档注释，
避免将来有人觉得二分更简洁而改回去。
