# 变异演练 · M3 四视图

> 口径同 [M1](M1.md)：每个变异对应**一条写下来的决定**，
> 问的是「这条决定被人无意中改掉，我们当场知不知道」。

这一轮跑了三十多个变异，全部记在下面。真正值钱的是**活下来的那七个**
—— 它们各自暴露了一条「看着有守卫、其实没有」的测试。

## 1. 活下来的七个

| # | 变异 | 为什么没抓到 | 补法 |
|---|---|---|---|
| S-1 | `_maxSpanDays` 62 → 400 | 上界只有下侧用例，注释描述的后果一条测试都没有 | 加「刚过界一天就缺席」，±1 两侧都红 |
| S-2 | 越界用例写成「第 70 天」时，62 → 63 | 上界被夹在**区间**里，不是钉在点上 | 越界用例收到只过界一天 |
| S-3 | 拖动侧不夹比例 | 与读侧的夹取**互相掩盖**：松手后读到的已被读侧夹过 | 在手指没抬起来时断言 |
| S-4 | 读侧不夹（配置里存 0.99） | 只验「下半屏还在不在」，而 0.99 下还剩八像素，空态照样画得出来 | 量比例 |
| S-5 | 甘特命中框从前往后找 | 夹具是两根整天的条，前后相接却不重叠，顺序无所谓 | 换成两根半小时的，框被撑到最小长度才真的叠上 |
| S-6 | 甘特条的顶端写死 0 | 探针只验「里面点得中」，而写死之后那个点仍落在条里 | 补一条「条的上方点不中」 |
| S-7 | 展开里注入真的 O(n²) | **基准量错了对象**，见 §3 | 改量排布函数 |

S-3 那条是 [testing-strategy §3.1](../testing-strategy.md) 记过的
「两处防御互相掩盖」又一次现身。S-5 与 S-6 是同一个形状的两半：
**只验「该在的在」，不验「不该在的不在」**，对整体平移这类改动是瞎的。

## 2. 时间轴那条：夹具短了一天

`effectiveEnd` 接上之后，「时间轴改回读 `endDate`」这个变异分两次才抓住：

1. 第一次没红 —— 守卫断言的是**行的访问器**，不是画出来的块。补了块的断言。
2. 补完之后「改回 `endMinute`」红了，「改回 `endDate`」**仍然没红** ——
   夹具里阶段只跨到当天 12:00，有效结束与存储结束**是同一天**，
   日期那一侧区分不开。补了一条越过午夜的。

> 一个访问器有两个分量（日期、时刻）时，夹具必须让**两个分量都不同**，
> 否则只验到了其中一个。

## 3. 基准第一版是条永远绿的测试

「条数翻倍耗时不该翻四倍」原本量的是 `expandInWindow`。
往里注入一个真的 O(n²)（每行扫一遍全表），**测试照样绿**。

查下去：正常情况的比值是 **0.95** —— 一千条与两千条一样快。
耗时压根不由任务数主导（时区解析、规则展开这些固定开销盖过了循环），
注入 O(n²) 之后比值也只到 1.71，阈值放到 6 自然抓不住。

> **量错了对象的基准，就是一条永远绿的测试。**
> 而它的破绽是可读的：比值远小于「输入增长的倍数」时，
> 说明被测的东西不由那个输入主导。

改成量排布函数（纯的、没有固定开销）之后又撞见第二件事：
先量 A 再量 B 的话，A 要替 B 付 JIT 编译的账，比值 **0.79～0.95**。

> **比值小于 1 本身就是「量法坏了」的信号，不是「代码很快」。**

两边都先跑一遍再计时。最终实测：

| 实现 | 比值 |
|---|---|
| 现在这版 | 1.28 / 1.35 / 1.72 |
| 注入 O(n²) | 4.15 / 4.51 |

阈值 3 落在中间，两侧各留一倍多余量。

#### 一条关于演练本身的教训

这一轮的还原用了 `git checkout <file>` —— 而那个文件里**有未提交的重构**。
一条命令把重构抹了，紧接着的「还原」跑出来是编译失败，
而失败信息的末行长这样：

```
C:/.../test/presentation/app_shell_test.dart: loading ...
```

看着像正常输出。要不是随后的 `dart analyze` 报了六个
`undefined_function`，这次重构会整个丢掉。

> **判据**：变异演练的还原一律用**文件备份**（`cp` 到 scratchpad 再拷回），
> 不用 `git checkout` —— 演练总是在未提交的代码上做的，
> 而 `git checkout` 还原的是 HEAD，不是「变异之前」。
>
> 附带一条：`flutter test | tail -1` 不能用来判断成败。
> 编译失败时末行是一行 loading，看不出红。要 grep
> `All tests passed|Some tests failed`。

### 评审补做：整体平移（位置 vs 形状）

评审会话拿一条我没做过的变异问了「要不要补 oracle」：
**把甘特的起止整体平移一天**（时长不变、不倒挂、不越界）。

我自己复现的结果：

| 变异 | 红的 |
|---|---|
| `_place` 起止同时 `+ minutesPerDay` | G-01、G-06 |

（评审那侧报的是 G-01/G-04/G-06/G-07 四条 —— 平移的落点不同，
红的条数就不同。**数目不重要，重要的是哪一类红**：
两次都是 G 系列全包，而**四条不变量一条没红**。）

结论与评审一致：**不用补 oracle**，因为位置已经由 G-01..G-07 钉住了。
但这个分工得写下来，否则将来有人加一条不变量、顺手删一条 G 用例，
平移盲区就重新打开 —— 记在
[view-specs §4.5.1](../../03-design/view-specs.md)。

### R-52，以及它撞出来的那个崩溃

| `all_day_conversion_test.dart` | 纯函数，压根不知道有 `UpdateTaskFieldsCommand` 这回事 |
