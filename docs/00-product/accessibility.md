# 无障碍声明

> 目标：**WCAG 2.1 AA**。本篇如实记录达到了哪些、**没达到哪些**、
> 以及每一条由什么盯着 —— 没有验证机制的「符合」等于没说。
>
> 状态列的含义：**已达标**＝有自动化守卫且当前全绿；**已知偏离**＝
> 明确不达标，有代偿措施；**未实现**＝功能本身还没做。

## 2. 已知偏离：控件边界的对比度（1.4.11）

### 2.1 事实

未选中的 Chip、输入框这类控件，其边界与页面底的对比度实测：

| 边界 | 对比 | 比值 |
|---|---|---|
| 凹陷底 vs 页面底（亮） | `#F5F1EA` vs `#FDFBF7` | 1.09:1 |
| 极淡描边 vs 页面底（亮） | `#EDE7DD` vs `#FDFBF7` | 1.19:1 |
| 凹陷底 vs 页面底（暗） | `#141317` vs `#1B1A1F` | 1.07:1 |
| 极淡描边 vs 页面底（暗） | `#35323C` vs `#1B1A1F` | 1.38:1 |

WCAG 1.4.11 要求 3:1。**这几条不达标。**

### 2.2 为什么不改

不是实现疏忽。[设计系统 §2.2](../03-design/design-system.md) 把
canvas / card / sunken 三个表面刻意设计得极为接近，并写明
「优先用留白代替线」。整套「可爱清新」的观感有相当一部分来自这个低反差；
把边界拉到 3:1 会让描边明显变硬，观感偏「清晰」而非「清新」。

当前调色板里也没有够用的中性色可借用 —— `text.disabled` 对 canvas
只有 2.34:1。要达标就得新增一个专用 token 并重新平衡整套中性色。

这是**产品取舍**，已显式决定并记为 NFR-A11Y-05。

### 2.3 代偿（硬性，不是安慰）

不达标的只有「一眼看出这是个可点的东西」这一件事。
「它是什么、它现在什么状态」全部达标：

1. **控件状态一律多重承载，不许只靠边界。**
   `SelectableChip` 的选中态由**填充 + 勾 + 标签色**三者共同承载 ——
   把边界整个去掉，选中与未选中仍然分得出。
   由 `test/design/component_assertions_test.dart` 的「选中态有勾」
   及其对照组（「未选中时没有勾」）守着 —— 后者防的是「一律画勾」
   这种能让前者变绿、却让选中态消失的退化实现。
2. **文字与承载状态的图形不放宽**：仍分别是 4.5:1 与 3:1，
   由三层守卫盯着（见 §3）。
3. **新增控件必须遵守第 1 条。** 一个只用边界表达状态的控件
   会让这整个代偿失效。

### 2.4 复审条件

以下任一发生时，这条偏离要重新拿出来评估：

- 用户反馈「找不到能点的地方」；
- 引入表单密集的界面（任务编辑器）后，输入框边界的问题比 Chip 更突出；
- 中性色因别的原因重新调整 —— 那时顺带解决的成本最低。

## 3. 对比度是怎么保证的：三层，各管各的

| 层 | 验什么 | 抓得到什么 | 抓不到什么 |
|---|---|---|---|
| token 全空间穷举 | 用户可配主色的**整个 24 位空间**派生后都达标 | 派生规则本身有洞 | token 被用错地方 |
| 文档数字重算 | 文档里每个实测值都由 WCAG 公式重算 | 文档与代码不同步、手写的错数字 | 同上 |
| **用法级渲染树配对** | 渲染组件后，每段文字与它**真正压着的背景**配对 | token 用错地方、字面量颜色、主题插值出的中间色、半透明叠加 | 没进画廊的组件 |

第三层是补的最晚的一层，**第一次跑就抓到一个当时全绿的缺陷**：
任务卡片的已完成标题用了发丝分隔线的颜色当文字色，实测 1.23:1。
当时断言型 32 条、快照型 6 张全绿，而且人看过那张 golden，
把「淡到读不出」读成了「完成态变淡，符合预期」。

**记在这里是因为它改变了我们对「看过图」的信任度**：人眼看「淡」
和仪器量「1.23:1」是两件事，只有后者能判「读不读得出」。
详见 [testing-strategy §7.3](../05-engineering/testing-strategy.md)。

## 4. 字号缩放

NFR-A11Y-02 字面只写了系统 200%，**实际最坏值是 280%** ——
应用内 `theme.fontScale` 最大 1.4，与系统 2.0 相乘。
布局断言与 golden 都覆盖到 2.8×（[设计系统 §3.4](../03-design/design-system.md)）。

按钮与 Chip 的高度是 `minHeight: 48` 而不是固定 48，就是为这个：
固定高度在 2.8× 下会把标签挤出去。

## 5. 已知的验证盲区

诚实记录，避免把「测过了」当成「没问题」：

- **中文排版的真机保真度**。测试环境没有中文字体，golden 里汉字是
  .notdef 方框；线上中文走系统字体，各家 OEM 不同。这个缺口**堵不上** ——
  不存在一个「正确的」中文基准图。所以「大字号下不破版」由断言型用
  **任何字体下都挤**的极端标签来验规则本身，不依赖某个字体的度量。
  （拉丁与数字这一半已经可信：Quicksand 随包，且在测试环境里真实加载。）
- **真机读屏未测**。语义树上的断言（角色、状态、标签）已有，
  但没有在 TalkBack 上跑过端到端。
- **动效与本地化未实现**，谈不上验证。
