# 产品愿景与范围

## 1. 一句话定位

**一个不让人有压力的每日计划助手**：把「今天要做什么」以最少的操作记下来，用最舒服的方式看见它，并在该做的时候轻轻提醒一下。

## 2. 目标用户与场景

| 用户画像 | 典型场景 | 对产品的要求 |
|---|---|---|
| 个人日常规划者 | 早上花 1 分钟排今天的事，晚上勾掉 | 新增要快、勾选要爽、视觉要轻松 |
| 有长周期目标的人 | 「毕业设计」拆成 5 个阶段，跨 3 个月 | 需要**阶段事项**与跨天进度可视化（竖向甘特） |
| 有固定节律的人 | 每周一三五健身、每月 1 号交房租 | 需要**定时计划**，且能单独跳过某一次 |

**明确不服务**：多人协作、团队任务分配、工时统计与考核。本产品是**单人、离线优先**的工具。

## 3. 设计基调：可爱清新

不是「幼稚」，而是**低压力感**。三条硬约束（细则见 [设计系统](../03-design/design-system.md)）：

1. **低饱和高明度**：主色系走奶油／薄荷／樱花色，避免高饱和红黄制造焦虑。
2. **圆润**：全局大圆角（16–24dp），无锐角卡片，图标用圆头线条。
3. **有呼吸**：留白充足，动效克制且有回弹感（`easeOutBack` 类曲线），但**任何动效都可在设置里关闭**（无障碍与低端机）。

> ⚠️ 反面清单：不用红色感叹号做逾期提示（改用暖橙 + 文案）、不用进度条羞辱用户（不显示「你已落后 N 天」）、不做打卡断签惩罚。

## 4. 范围边界

### 4.1 V1 范围（本次交付的 Android 包）

对应 [路线图](../07-roadmap/roadmap.md) 的 M0–M5。

- ✅ 三种任务形态：单项 / 阶段事项 / 定时重复（含单次例外）
- ✅ 四种视图：时间轴、列表、日历、竖向甘特
- ✅ 配置中心：主题、分类管理、视图偏好、提醒偏好、行为偏好、数据导入导出
- ✅ 本地通知提醒
- ✅ 本地数据落盘 + 全量 JSON 导入/导出（为云同步预留信封字段）

### 4.2 V1 明确不做（但架构必须留口）

| 能力 | 期次 | 架构上现在就要做的准备 |
|---|---|---|
| 桌面小组件 | V2 | 数据层提供不依赖 UI 的 `TodayDigest` 查询；DB 走可跨进程访问的文件路径 |
| 通知栏常驻消息 | V2 | 通知模块与任务查询解耦，通知内容由纯函数生成 |
| 云端同步 / 云端恢复 | V3 | 每条记录带同步信封（`updatedAt`/`deletedAt`/`revision`/`lastWriterId`），变更写 outbox |
| 云端读取任务并发邮件 | V3 | 数据可被服务端独立解析：schema 版本化 + 纯 JSON 可导出，不依赖客户端逻辑 |
| 语音识别 + AI Agent | V4 | 所有写操作收敛到 `TaskCommand` 用例层，Agent 只需产出 Command，不碰 UI |

> 这些「留口」不是口号。每一条在 [架构总览](../01-architecture/overview.md) 与 [数据模型](../02-domain/data-model.md) 中都有对应的具体条款，M1 完成时会逐条验收。

### 4.3 长期也不做

- 不做账号体系（V3 的云同步走用户自带存储／端到端加密备份，不建中心化账号）
- 不做广告、不做付费墙
- 不做社交分享流

## 5. 成功判据（V1）

| 判据 | 可度量标准 |
|---|---|
| 新增一个任务足够快 | 从点开 App 到任务落库 ≤ 3 次点击、≤ 5 秒 |
| 视图切换不卡 | 中端机 1000 条任务下，视图切换与滚动稳定 60fps（掉帧率 < 1%） |
| 数据不丢 | 强杀 App / 断电后重启，已提交的写入 100% 可见（由持久化集成测试覆盖） |
| 提醒准时 | 允许精确闹钟时，触发误差 ≤ 60 秒；被系统限制时有降级提示 |
| 冷启动快 | 中端机冷启动到首屏可交互 ≤ 1.5 秒 |
