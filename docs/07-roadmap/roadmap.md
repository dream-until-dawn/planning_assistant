# 路线图与里程碑

> 原则：**每个里程碑都有可验收的产出**，且验收标准是可自动化检验的，不是「感觉差不多了」。
> 没通过验收的里程碑不进入下一个 —— 尤其 M1，它承载了所有「为后续留口」的兑现。

## 总览

| 版本 | 里程碑 | 产出 |
|---|---|---|
| **V1** | M0 工程基建 | 可构建的空壳 + CI + 规范落地 |
| | M1 领域内核 | 模型 + DB + 重复引擎 + 命令管道（**无 UI**） |
| | M2 基础 UI | 设计系统 + 列表视图 + 任务增删改 |
| | M3 四视图 | 时间轴 + 日历 + 竖向甘特 |
| | M4 配置与提醒 | 配置中心 + 本地通知 |
| | M5 打磨出包 | 性能、无障碍、导入导出、签名发布 |
| **V2** | 桌面小组件与通知栏 | |
| **V3** | 云同步 / 恢复 / 邮件 | |
| **V4** | 语音与 AI Agent | |

## M0 · 工程基建

**产出**：一个能构建出 APK 的 Flutter 工程骨架，CI 跑通，规范落地。

| 任务 |
|---|
| `flutter create` 骨架，按[模块与目录规范](../01-architecture/module-map.md)建目录 |
| 配置 Gradle 阿里云镜像、desugaring、compileSdk、minSdk |
| `analysis_options.yaml` + 自定义 lint |
| CI：analyze / codegen 校验 / test / guard / build |
| 架构守卫测试骨架（此时应该是**通过**的，因为还没代码可违规） |
| 完成[环境探针结论 §6 的 M0 检查表](../05-engineering/environment-notes.md)全部条目 |

**验收**

- [ ] `flutter build apk --debug` 成功
- [ ] CI 全绿
- [ ] `compileSdk` 决策已定（能否移除 `permission_handler` 降回 36）
- [ ] `uuid` 的 v7 API 已实测确认（或已自实现）
- [ ] 重复引擎探针 P-3/P-4/P-5 完成，结论写入文档
- [ ] 断网启动无网络请求（字体已打包）
- [ ] **故意写一个违反分层的 import，确认守卫测试变红** ← 验证守卫真的有效
- [ ] 同样地：故意留一个 `assert(` 在 `lib/domain/`，确认 lint 守卫变红
- [ ] `python tool/check_doc_links.py --self-test` 进 CI 且自检通过
- [ ] **以上每一条都把「变红的输出」贴进 M0 记录**，而不是只写「已验证」

> 最后几条是本项目的规矩：**任何守卫机制建立时，必须当场证明它能失败**，
> 否则它就是又一个「永远绿的测试」。这条规矩适用于守卫、lint、校验脚本、CI 门禁
> —— 凡是「报绿就放行」的东西都适用。详见[测试策略 §1.4](../05-engineering/testing-strategy.md)。
>
> 文档链接校验器已按此完成两步验证（自检 + 对真实仓库注入坏链），失败输出留档在 §1.4。

## M1 · 领域内核（最关键的里程碑）

**产出**：完整的领域模型、数据层、重复引擎、命令管道。**没有 UI**，全靠测试驱动。

| 任务 |
|---|
| `core/time`、`core/id`、`core/result` |
| 领域实体、值对象、状态机 |
| 重复引擎（含[必测用例 §6](../02-domain/recurrence-engine.md) 全表） |
| Drift 表定义、迁移基线、DAO、Repository 实现 |
| 同步信封 + outbox 写入 |
| `TaskCommand` 全集 + `CommandDispatcher` |
| 导入导出 DTO + JSON Schema |

**验收**（这是全项目最严的一次验收）

- [ ] 领域层覆盖率 ≥ 90%，数据层 ≥ 80%
- [ ] [重复引擎必测用例](../02-domain/recurrence-engine.md#6-必测用例清单)全部通过（≥ 40 条）
- [ ] [状态机必测用例](../02-domain/task-lifecycle.md#7-必测用例)全部通过，含每一条非法迁移
- [ ] 四个时区（含带 DST 的时区）参数化测试通过
- [ ] **`UNTIL` 时区边界用例 R-07..R-09e 通过**，且 `COUNT` 对照组四时区一致
- [ ] **`encodeRrule()` 的字节等价往返测试通过**（含 `UNTIL` 的规则必须带 `Z`）
- [ ] 领域层与数据层**零 `assert` 表达的不变量**（lint 守卫通过）
- [ ] **回放一致性测试通过**：清库 → 按 outbox seq 回放 → 状态等价
- [ ] **导出导入往返测试通过**：逐表逐字段比对
- [ ] 导出样例通过**独立于客户端的**脚本（Python/Node）的 JSON Schema 校验 ← 提前证明「服务端可独立解析」
- [ ] 重复展开基准：1 年 ≤ 50ms
- [ ] **第一次变异演练完成**，报告入库 `docs/05-engineering/mutation-drills/M1.md`
- [ ] **「留口」逐条验收**（见[架构总览 §6](../01-architecture/overview.md)）：
  - [ ] 纯 Dart 测试（不启动 Flutter binding）能取到 `TodayDigest`
  - [ ] 每个 `TaskCommand` 的 JSON 往返测试通过
  - [ ] 架构守卫确认无写操作绕过命令管道

## V3 · 云同步 / 恢复 / 邮件

**前置**：先定[云同步预研](../04-platform/future-sync.md)的 A-1（后端形态），并补上墓碑清理的已知缺口。
建议在 V1 阶段就完成「用独立脚本校验导出 JSON」这一项 —— 成本低，且能提前证明数据模型设计是对的。

## V4 · 语音与 AI Agent

**前置**：先收集 200 条真实中文口语语料并评测准确率。
**若「说一句话」不比「点三下」快，不做。**

---

## 里程碑之间的硬规矩

1. 上一个里程碑的验收未全部通过，不开始下一个。
2. 每个里程碑结束时更新受影响的文档（不是「有空再补」）。
3. 每个里程碑结束时打 tag：`v0.1.0-m1` 这样。
4. M1 与 M5 各做一次变异演练，报告入库。
