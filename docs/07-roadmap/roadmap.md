# 路线图与里程碑

> 原则：**每个里程碑都有可验收的产出**，且验收标准是可自动化检验的，不是「感觉差不多了」。
> 没通过验收的里程碑不进入下一个 —— 尤其 M1，它承载了所有「为后续留口」的兑现。

## 总览

| 版本 | 里程碑 | 产出 |
|---|---|---|
| **V1** | M0 工程基建 | 可构建的空壳 + CI + 规范落地 |
| | M1 领域内核 | 模型 + DB + 重复引擎 + 命令管道（**无 UI**） |
| | M2 基础 UI | 设计系统 + 列表视图 + 任务增删改 |
| | M3 四视图 | 时间轴 + 日历 + 竖向甘特 |

| **V2** | 桌面小组件与通知栏 | |
| **V3** | 云同步 / 恢复 / 邮件 | |
| **V4** | 语音与 AI Agent | |

回收站这一条链路是**分两步接完**的，中间那一步的状态值得记一笔：
删除、回收站、恢复都有了，而超期物理清理没有 —— 于是回收站**只进不出**，
界面上也不敢写「还剩几天」，因为那是在承诺一件不会发生的事，
只能干巴巴地显示删除日期。

补上清理之后那句承诺才兑得了。同时把「还剩几天」和「该不该清」
收成同一个函数（`timeUntilPurge`）：两处各算一遍的话，
删除 29 天 20 小时的任务会显示「还剩 1 天」而它今晚就没了。

**FR-TASK-03 的验收栏点了五种重复，两种一直没落地**：「每月 15 号」
与「每月最后一个周五」。这两种最值得记的不是补它们花了多少工夫，
而是**三层测试都是绿的**：引擎的黄金用例 R-10…R-13 就是这两种、
一直在跑；可达性守卫扫的是「草稿的字段都有控件」，而它们从没变成过字段；
往返表里也没有它们 —— 它们在「界面表达不了」那一组，
还各有一条测试**钉着它们表达不了**。

三个全集都来自代码，没有一个来自需求。补的时候于是多加了一条
锚在需求上的守卫（`fr_task_03_shapes_test.dart`），
判据记在 [testing-strategy §1.15](../05-engineering/testing-strategy.md#115-完备性守卫只能守住它认识的那个全集)。

顺带把「每月最后一天」也做了（`BYMONTHDAY=-1`）：实测 2026 年
`BYMONTHDAY=31` 只命中 7 个月 —— 短月份按 RFC 5545 是**跳过**、
不是夹到月末，想月末结账的人选 31 号会静悄悄漏掉 5 次。
界面上选到 29 号以上会直说这件事。

**FR-VIEW-07 是同一次盘点里翻出来的**：四个视图的加号走的是同一个
**无参**回调，`TaskEditorPage` 也不接受任何初值 —— 于是「快速新增
能带上下文」这条一个字都没落地。日历翻到 9/20 点加号，
建出来的任务落在「随时」区，用户得把刚才正看着的日期再选一遍。

做法是一条 `/task/new?date=…&minute=…`：视图只喊「在这儿新建」，
由组合根拼成路由 —— 视图不认识路由表（§7.2），顺带这条路由
将来能被小组件、语音入口直接唤起。

**顺手差点堵死另一条路**：加号一开始无条件带上聚焦日，
于是列表里再也建不出「随时」任务（FR-VIEW-01 点了名的一档），
两条既有测试一起变红。改成只在「对着某一天」的视图里带
（`ViewKind.anchorsToDay`）。修 A 的时候把 B 堵上，
是这一晚反复出现的形状 —— 好在这次是测试先说的。

#### FR-TASK-07 当晚补完

补的路径是「领域判据一处、界面一处」：

- `stageStatusFor` 回答「这一次的这一步做完没有」，
  **不重复的任务看 `Stage.status`，重复的看 `StageOccurrenceState`**。
  查不到时回落 `pending` 而**不是**阶段自己 —— 回落到阶段自己的话，
  旧毛病换个地方又长出来（变异 S-01 验的就是它）。
- 勾选放在**单次动作弹层**里，不在编辑器里：编辑器编的是整条任务，
  在那儿勾等于把每一周都标完成。view-specs §4.3 那句
  「点击段落…可就地标完成」里的「就地」，永远发生在某一次上。

顺带收了一处将来必定分叉的地方：三个视图此前各写一遍
`occurrenceCardData(row, categories, stages[row.taskId])`，
加「这一次的状态」要改三处，漏一处的表现是那个视图的进度
与另外两个说的不一样、而且不报错。现在统一走 `cardDataOf(ref, row)`。

还修了一个顺带撞出来的功能缺陷：弹层加上阶段清单之后撑破了自然高度，
`Column(mainAxisSize: min)` 不滚，**最下面的「跳过这一次」够不着了**。

归档（FR-TASK-08 的另一半）也补上了：编辑页的归档入口 + 设置里的
「已归档」列表。三条可见性谓词（活跃 / 归档 / 回收站）现在**各有一个
界面出口**，而「回收站里混进归档任务」这类分叉有测试盯着。

顺带补上的两处（都是接时间轴时才露出来的）：

- 重复任务的每一次**从来没有结束时刻** —— `durationMinutes` 声明了、
  引擎读它、引擎的测试也测了，但没有任何地方**写**它
  （[测试策略 §1.9](../05-engineering/testing-strategy.md#19-两侧都测到了中间那根线没人接)）；
- 展开按开始日期筛，于是「昨晚 22:00 干到今早 6:00」在今天的时间轴上
  是空的。改成按覆盖区间收。

**验收**

- [x] [甘特布局必测用例](../03-design/view-specs.md#45-布局算法必测用例) G-01..G-07 通过
- [x] [视图切换一致性](../03-design/view-specs.md#5-视图切换的一致性fr-view-0506)四条集成测试通过
- [ ] 1000 条任务下四视图滚动掉帧率 < 1%（profile 模式实测）—— **只做了一半**：
      布局计算这一半有基准（`test/application/view_layout_benchmark_test.dart`，
      含一条挡 O(n²) 的增长曲线用例）；**掉帧率本身还没在真机 profile 模式量过**。
      模拟器的帧时间不代表真机，量了也说明不了问题，所以不拿它充数。
- [x] 集成测试 J-02、J-03 通过

## 里程碑之间的硬规矩

1. 上一个里程碑的验收未全部通过，不开始下一个。
2. 每个里程碑结束时更新受影响的文档（不是「有空再补」）。
3. 每个里程碑结束时打 tag：`v0.1.0-m1` 这样。
4. M1 与 M5 各做一次变异演练，报告入库。
