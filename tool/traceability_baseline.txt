# 可追溯性豁免表的基线 —— **只许缩短**。
#
# 这张表记的是「当前允许有哪些 V1 需求没有测试点名」。
# `check_traceability.py` 会核对：`EXEMPT` 必须是它的子集。
#
# ## 为什么要棘轮
#
# 豁免表本身是诚实的（每条都写了由谁承担）。要防的是**它长得比覆盖快** ——
# 那时它就从「记账」变成了「仪式」：谁都可以往里加一行让门禁变绿，
# 而加的时候没有人会拦。
#
# 加一条豁免现在要**同时改两个文件**，其中这一个除了放行什么也不做。
# 那一步不是麻烦，是让「我要放行一条需求」变成一个需要说出口的动作。
#
# ## 怎么改
#
# - **删除**一行：随时可以，那表示某条需求真的被测到了；
# - **新增**一行：连同 `EXEMPT` 里的理由一起加，理由必须写明由哪个
#   里程碑或哪份文档承担（工具会检查格式）。
